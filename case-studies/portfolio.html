Portfolio Architecture (Dev/Prod)

This diagram summarises the PR-only publishing flow, Cloudflare security gates, and the rebuild triggers used to keep dev and prod in sync.

flowchart LR
  subgraph Access["Security (ADR-006)"]
    AccessCF["Cloudflare AccessGitHub OAuth + Org/Team + MFA"]
    Jwt["CMS Worker JWT verify+ shared keys"]
  end

  subgraph Admin["Admin UI (Cloudflare Pages)"]
    AdminDev["dev.admin.portfolio.tacsa.co.uk"]
    AdminProd["admin.portfolio.tacsa.co.uk"]
  end

  subgraph CMS["CMS API Layer"]
    Proxy["Pages Function /api/*adds x-cms-read-key / x-cms-key"]
    Worker["CMS Worker (PR-only writes)"]
  end

  subgraph GitHub["GitHub (Source of Truth)"]
    DevBranch["dev branch"]
    MainBranch["main/master branch"]
    PR["Pull Request"]
  end

  subgraph Pages["Cloudflare Pages (Deploys)"]
    DevSite["dev.portfolio.tacsa.co.uk"]
    ProdSite["portfolio.tacsa.co.uk"]
  end

  subgraph Hooks["Rebuild Triggers (ADR-010)"]
    Action["GitHub Actions (supporting repo)"]
    HookDev["Deploy Hook (dev)"]
    HookProd["Deploy Hook (prod)"]
  end

  AccessCF --> AdminDev
  AccessCF --> AdminProd
  AdminDev --> Proxy --> Worker --> DevBranch
  AdminProd --> Proxy --> Worker --> DevBranch
  Worker --> PR --> MainBranch

  DevBranch --> DevSite
  MainBranch --> ProdSite

  Action --> HookDev --> DevSite
  Action --> HookProd --> ProdSite

  • PR-only writes via the CMS Worker (ADR-004).
  • Cloudflare Access + JWT verification + shared keys (ADR-006).
  • Deploy hooks trigger rebuilds from supporting repos (ADR-010).
  • Branch-to-environment mapping for dev/prod (ADR-012).
